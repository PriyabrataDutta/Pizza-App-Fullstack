# Canonical Database Schema — Initial Blueprint

This document is the schema design authority. Antigravity must refine field nullability, constraints, indexes and RLS before implementation. SQL migrations are the executable history and must match this document.

## Conventions
- PostgreSQL and Supabase.
- UUID primary keys, generally generated by `gen_random_uuid()`.
- `timestamptz` for timestamps.
- `created_at` and `updated_at` on mutable entities where useful.
- Currency represented as an ISO currency code plus integer minor units (e.g. paise). Do not use floating-point arithmetic for money.
- Foreign keys and check constraints for relational/business invariants.
- Snapshot historical order details so menu/address edits do not alter old orders.
- Role and module access are server-authorized, never trusted from client input.

## Tables

### profiles
- `id uuid primary key references auth.users(id) on delete cascade`
- `full_name text`
- `phone text`
- timestamps

### staff_users (dashboard accounts; replaces the earlier `user_roles` sketch)
- `id uuid primary key references auth.users(id) on delete cascade`
- `full_name text`, `email text unique`
- `role text` in (`super_admin`, `manager`, `staff`)
- `status text` in (`active`, `inactive`)
- `must_change_password boolean` (true after creation or a password reset)
- `branch_id uuid null` reserved for future multi-branch scope; unused while there is one outlet
- `created_by`, `created_at`, `updated_at`
- A database trigger refuses to delete, deactivate or demote the last active `super_admin`.
- Customers are not dashboard users and never get a role here.

### user_modules (module grants)
- `(user_id, module)` primary key; `access` in (`view`, `manage`)
- `module` in `overview`, `orders`, `menu`, `categories`, `customers`, `offers`, `delivery`, `reports`, `settings`
- Super admins implicitly hold every module with `manage` and have no rows.
- `users` (Users & Access) is never assignable: super admin only.

### audit_log
- `actor_id`, `actor_email`, `action`, `target_id`, `target_email`, `details jsonb`, `created_at`
- No foreign keys, so history survives deleting the people it mentions.
- Actions recorded: `login`, `user_created`, `user_updated`, `user_deleted`, `password_reset`, `password_changed`.

### branches
- `id uuid primary key`
- `name text`
- `slug text unique`
- address/contact fields
- `is_active boolean`
- timestamps

### categories
- `id uuid primary key`
- `name text`
- `slug text unique`
- `image_url text null`
- `sort_order integer`
- `is_active boolean`
- timestamps

### products
- `id uuid primary key`
- `category_id uuid references categories(id)`
- `name text`
- `slug text unique`
- `description text`
- `image_url text`
- `dietary_type text` constrained to supported values
- `is_spicy boolean`
- `is_bestseller boolean`
- `is_active boolean`
- timestamps

### product_variants
- `id uuid primary key`
- `product_id uuid references products(id)`
- `name text` (e.g. Small, Medium, Large)
- `sku text null`
- `price_minor bigint` with non-negative constraint
- `currency char(3)`
- `is_available boolean`
- timestamps
- Unique product/name or SKU constraints as appropriate.

### customization_groups
- `id uuid primary key`
- `name text`
- `selection_required boolean`
- `min_selections integer`
- `max_selections integer`
- `is_active boolean`
- Validate min/max consistency.

### customization_options
- `id uuid primary key`
- `group_id uuid references customization_groups(id)`
- `name text`
- `price_delta_minor bigint`
- `currency char(3)`
- `is_active boolean`
- timestamps

### product_customization_groups
- `product_id uuid references products(id)`
- `group_id uuid references customization_groups(id)`
- `sort_order integer`
- composite primary key `(product_id, group_id)`

### addresses
- `id uuid primary key`
- `customer_id uuid references profiles(id)`
- `label text`
- recipient/contact fields
- address lines, locality, city, region, postal code
- delivery instructions
- `is_default boolean`
- timestamps
- Customer access restricted to owner and authorized server workflows.

### coupons
- `id uuid primary key`
- `code text unique` normalized consistently
- `discount_type text` constrained to `fixed` or `percentage`
- `discount_value bigint`
- `minimum_order_minor bigint`
- `maximum_discount_minor bigint null`
- `currency char(3)`
- `starts_at timestamptz`
- `expires_at timestamptz`
- `usage_limit integer null`
- `per_customer_limit integer null`
- `is_active boolean`
- timestamps

### delivery_zones
- `id uuid primary key`
- `branch_id uuid references branches(id)`
- `name text`
- postal-code/coverage definition appropriate to the demo
- `delivery_fee_minor bigint`
- `minimum_order_minor bigint`
- `estimated_delivery_minutes integer`
- `is_active boolean`
- timestamps

### restaurant_settings
- `id uuid primary key`
- `branch_id uuid references branches(id)`
- `currency char(3)`
- `tax_rate_basis_points integer` or an explicitly defined tax policy
- opening-hours representation
- contact and display settings
- `minimum_order_minor bigint`
- timestamps
- Unique branch scope.

### orders
- `id uuid primary key`
- `order_number text unique` human-readable display ID
- `customer_id uuid null references profiles(id)` only if guest checkout is explicitly supported
- `branch_id uuid references branches(id)`
- `status text` constrained to the documented order lifecycle
- `payment_method text`
- `payment_status text`
- `currency char(3)`
- `subtotal_minor bigint`
- `discount_minor bigint`
- `tax_minor bigint`
- `delivery_fee_minor bigint`
- `total_minor bigint`
- delivery-address snapshot fields
- `coupon_id uuid null references coupons(id)`
- `idempotency_key text`
- `created_at`, `updated_at`
- Unique idempotency scope, defined carefully (e.g. customer + key).
- Check non-negative monetary fields and consistency rules where practical.

### order_items
- `id uuid primary key`
- `order_id uuid references orders(id) on delete cascade`
- `product_id uuid null references products(id)` for historical preservation if catalog item is later removed
- `variant_id uuid null references product_variants(id)`
- `product_name_snapshot text`
- `variant_name_snapshot text`
- `quantity integer` constrained greater than zero
- `unit_price_minor bigint`
- `line_total_minor bigint`
- `currency char(3)`
- timestamps

### order_item_options
- `id uuid primary key`
- `order_item_id uuid references order_items(id) on delete cascade`
- `option_id uuid null references customization_options(id)`
- `option_name_snapshot text`
- `price_delta_minor bigint`
- `quantity integer` constrained greater than zero if option quantity is supported
- timestamps

### order_status_history
- `id uuid primary key`
- `order_id uuid references orders(id) on delete cascade`
- `previous_status text null`
- `new_status text`
- `actor_user_id uuid null references profiles(id)`
- `reason text null`
- `created_at timestamptz`
- Append-only for ordinary users; trusted operation writes history with each transition.

### payments
- `id uuid primary key`
- `order_id uuid references orders(id)`
- `method text`
- `status text`
- `amount_minor bigint`
- `currency char(3)`
- `provider text null`
- `provider_reference text null`
- `is_demo boolean`
- timestamps
- No real card data is stored.

### coupon_redemptions
- `id uuid primary key`
- `coupon_id uuid references coupons(id)`
- `order_id uuid unique references orders(id)`
- `customer_id uuid references profiles(id)`
- `discount_minor bigint`
- `created_at timestamptz`
- Enforce limits transactionally to prevent race conditions.

## Relationships
- One profile can have many addresses and orders.
- One category has many products.
- One product has many variants.
- Products can use multiple customization groups through a join table.
- Customization groups have multiple options.
- Orders have many items and status history records.
- Order items have many option snapshots.
- Orders may have payment records and coupon redemption records.
- Branches scope operational settings and delivery zones.

## Required database behavior
- Migrations are numbered and version-controlled.
- Seed script is repeatable and safe for a demo environment.
- Add indexes based on actual query patterns: orders by customer/date, branch/status/date, products by category/active, coupon code.
- Use transactions or trusted database functions for atomic checkout and coupon redemption.
- Never rely on client-supplied totals.
- RLS policies must be documented and tested.
- Do not expose service-role credentials to clients.

## Important implementation decision
Before final migrations, explicitly decide whether the demo supports guest checkout. If not, require authenticated customers and make `orders.customer_id` non-null. Do not leave ambiguous access rules.
